## Product boundary

The existing R04 Quest is the owner's real business objective. This lane adds one bounded original-POD-T-shirt research episode to that exact Goal. It does not replace the objective with a pilot template, manufacture a completed legacy experiment, or reopen a stopped/exhausted episode. The ordinary journey is: save/select the genuine Goal, choose a reviewed research profile and its supported public market/topic choices, review the complete question/source/price/financial packet, confirm the existing R05 operating policy, then Continue through the existing five-phase R07/R12 engine. The initial episode has planner, one source collection, exact-span selector, strategist and independent reviewer. TEST, REJECT and NEEDS_MORE_EVIDENCE remain honest outcomes. Creative and commerce have separate gates.

A separately approved, expiring Business bootstrap grant permits only this profile and a finite cumulative number of initial scopes. It expressly covers the two role-separated child verifier enrollments and their fixed windows. Grant and profile revocation, expiry, ownership change and current revision checks are enforced server-side. No browser input can supply authority/review hashes, operations, arbitrary plan JSON, provider quote JSON or credentials. It calls the existing owner-only endpoint and displays the nonsecret verifier bound to that Business, owner and grant. It remains available when no profile is enrolled. Preparing this reference enrolls nothing, creates no authority, obtains no quote and starts no provider work. The separately reviewed operator enrollment and ordinary owner financial confirmation remain subsequent steps.

Preparation registers only exact non-executable operations/adapters and an immutable setup/proposal. R05 itself writes genuine owner proposal/confirmation and cap records. It cannot write controller plans, attempts, dispatch markers, provider responses or receipts. Continue creates its plan through the existing R07 command.

## New private persistence and API review

The additive design introduces reviewed profiles, immutable category/root bindings, bounded bootstrap grants and revocations, immutable owner setups and activation receipts. All are RLS protected with no direct public/anon/authenticated/service-role table grants. The current-owner read projection is bounded. Owner mutations require a real authenticated owner session and the separately enrolled server bootstrap capability. Private helpers have no application-role EXECUTE.

R12 source scopes gain an explicit owner-initial origin/setup reference. Legacy references remain required in all historical variants, and in new owner-initial scopes funded by a legacy root. Only the exact native-Business variant permits null legacy references. A common trusted resolver supplies current/historical intent, source and funding bindings for plan validation, final reserve/dispatch, phase inputs, owner reads and result reconstruction.

The owner-initial static schema supports 1–4 explicitly selected markets. Historical geographic discovery still requires 2–4; the focused pilot keeps its exact own one-market profile. The new schema contains no private per-run values. Local domain validation requires exactly the selected countries once each, and single-market findings cannot claim comparative superiority over unstudied markets.

Stop must work before activation as well as during the existing research workspace. Revoking a confirmed-but-not-activated setup's exact R05 policy blocks activation. Already dispatched work and possible charges remain saved for bounded receipt reconciliation.

A distinct owner-initial funding revision may append a higher total to the same category/root only after the exact old total, proposed new total, all committed/pending costs and expected funding revision are shown and explicitly confirmed alongside R05.
