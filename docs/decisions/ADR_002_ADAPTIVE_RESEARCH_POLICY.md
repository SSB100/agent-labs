# ADR 002: bounded adaptive research proposal policy

Status: integration implemented in this branch and still unqualified; not production activation. Supersedes ADR 001's avoidance of numeric review checklists for new adaptive-format decisions only. Historical decisions and deployed formats are unchanged.

The owner approved US$10 total per run and up to ten combined additional follow-up, repair or pivot actions. A targeted reasoning review also consumes an additional action; a stronger model may be used only after its route is separately qualified. An action can require several paid phase calls; all must be exposed, quoted and counted. The run cap is not new money added to the root or Business ledger. Existing commitments, lifetime ceilings, expiry and unknown liabilities still constrain admission.

The provisional rubric rates attributable relevant evidence, decision-changing learning value, measurable bounded test design and feasibility from 0 to 2. Zero means absent/unsupported, one means partial but usable with explicit limitations, and two means specific supported sufficiency for the proposed experiment. TEST requires at least 6/8, every criterion at least one, test design two and no specific proposal blocker. Known hard failures yield REJECT. Other gaps yield NEEDS_MORE_EVIDENCE. Scores are ordinal reviewer judgments, not probabilities or commercial validation; calibration remains required. Pending future creative permissions alone are not proposal failures.

The pure module validates arithmetic and essential gates, not semantic truth or authorization. Runtime must verify cited evidence, concrete score rationales, hypothesis/measurement/stop rules and independent reviewer lineage. An identified negative finding counts as progress; a new URL, timestamp, hash or model paraphrase alone does not. Authenticated evidence/reasoning comparisons must establish that a question was resolved, narrowed or refuted before supplying a progress record.

The new reviewer contract attaches the exact immutable strategist test plan rather than allowing the reviewer to invent one. It requires positive, negative and inconclusive observations, a bounded window and stop rule. Unknown evidence IDs and scope/model identity mismatches fail validation. Semantic score/outcome disagreement is preserved with raw model outcome and conservative derived outcome, never repaired by polling for agreement. Exact normalized duplicate questions are removed only from derived additions with an audit count; raw response and inherited questions remain. Execution prerequisites are separate from actual identified input concerns and trusted present proposal omissions. Schema validation cannot establish that prose is substantively measurable or correct; independent semantic qualification remains mandatory.

Two nonprogress iterations trigger diagnosis, targeted evidence work, a bounded reasoning review or an in-scope pivot. They do not terminate the owner Goal. The current qualified pair supports targeted reconsideration, not a stronger-model claim. At most one reasoning review per stagnation episode is permitted; no polling models until agreement. Repairs do not reset stagnation. Missing feasible authority or an evidence wait pauses execution. Paid escalation consumes the shared action/call/budget allowance.

The current Goal has 19/32 children and 17/64 dispatches used: 13 child slots and 47 dispatches remain. R07 children are immutable phase capability slots, not individual calls. Create five NEW slots for this adaptive run and retain the genuine five-phase initial path. Up to ten four-call follow-ups plus those initial five calls totals 45 dispatches and five new children, fitting the original ceilings. Replanning, escalation or extra repairs still consume actual dispatches and cost, so all ten actions are not guaranteed. The combined ten-action ceiling counts high-level extra actions; each can have several paid phase calls. Initial five-phase work is separately counted and does not consume one of the ten extras. Every call has a distinct immutable action/phase attempt, request and receipt. Never reuse a closed predecessor capability slot or reset counters.

The new adaptive-format ledger must identify action ordinal, phase and exact dependencies. Existing legacy R07 attempts remain limited to four and retain successful-result and repair rules; do not route new successful-phase repetition through generic repair. New-format current-action result lookup and completion must never select an old phase result accidentally. This is a bounded branch of the existing controller, not a separate orchestrator framework. Reserve downstream selection, strategy and independent review costs/dispatches plus any missing new phase slots before retrieval or pivot. The pure policy derives required new children from distinct phase kinds absent from trusted createdPhaseSlots for this new run. Runtime and SQL must bind those slots to the exact current plan, count high-level action admission once, atomically reserve dependent completion capacity and release unused reservations without refunding incurred spend or counters.

This branch adds separate adaptive plan/scope/quote/grant contracts, exact predecessor/artifact pins, scoped conditional action transitions and the current installed POD capability. Integration includes controller, request/output runtime, owner server/UI, adapter and SQL changes; these remain subject to the acceptance gates below. The caller supplies server-validated action topology, required downstream calls, capability/route qualification, same-root authority and current committed-cost snapshots. Boolean authority and numeric scores from a model or browser are never trusted. Qualified stronger model routes and public-source boundaries must be included in the reviewed envelope. Generic Etsy niches, commerce, profit monitoring and R13–R18 execution remain separate capabilities.

Acceptance requires existing-format regression, SQL race/replay/tenant/financial tests, bounded action and dependent-review reservation tests, rubric semantic fixtures including episode 3 errors, exact-tree hosted gates and normal owner UI qualification before approved paid testing. This proposal does not claim deployment, a successful adaptive run or R12 completion.

The adaptive runtime uses a distinct owner_adaptive context and r12.discovery-adaptive-source.1 evidence lineage. Its action intent has one or zero new collections and the real run ceiling; run, action and original-root accounting snapshots remain explicit and separate. Legacy intent/dossier limits remain unchanged. The complete archive manifest and material negative findings are bound alongside an explicit active subset of at most six packs. Oversized complete contexts fail before reservation; no truncation is permitted. Current qualified routes remain Luna on Azure and independent Haiku on Bedrock. A reasoning_review with that pair is targeted reconsideration, not a claimed stronger-model escalation. New model choices need qualification before use.

Adaptive quote ceilings cover the actual larger request bounds, and actual adapter serialization stops at deliberately denied admission during preflight. Pure request, projection and preflight helpers contain no transport. The shared server adapter provides the dispatch boundary and must load the activated scope, current admitted action, immutable dependencies, qualified receipts, current ledger snapshot and installed knowledge before constructing the context. Preview/browser JSON is never that trusted context. The adaptive review preserves raw outcome and exact selected candidate identity, may recommend an in-scope next action, and anchors progress to exact prior findings plus stable source/span identity hashes; action-local E1 labels do not establish evidence novelty. Missing actionable recommendations pause without completing the owner Goal.



An omitted next-action recommendation on an otherwise valid NME result may trigger one Core-defined diagnostic reasoning review over the actual saved unresolved questions. It uses the existing strategist and independent-reviewer pair, consumes one extra action and two calls, and never changes the raw omission or counts as progress by itself. A durable per-scope normalized gap hash prevents repetition for the same questions. Explicit null/close decisions remain respected. SQL must reserve both calls and atomically claim the diagnostic; the pure proposal helper creates no authority.

Repair actions restart at a coherent context boundary: planner defects use all five phases, search or selection defects use search/selection/strategy/review, and strategy or review defects use strategy/review. Every actual call consumes dispatch capacity and quoted liability. Older action outputs are never relabeled as fresh strategy or collection results to make a one-call repair appear sufficient. The separately reviewed V2 source profile may contain six domains, allowing four retained historical sources plus two new reviewed sources; V1 stays at four. Every domain still needs its own review and must respect exclusions. This is a structural bound, not source enrollment.
