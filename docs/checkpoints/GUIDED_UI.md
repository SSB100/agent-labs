# Guided owner interface

## Scope

The owner-approved guided interface is delivered in bounded phases against existing workflow contracts. This is a private application, not a new orchestration runtime or a public marketing site. Existing routes, owner-scoped data and provider authority boundaries remain intact.

## Phase 1: truth and legibility

- Decision cards map known intervention types to their actual handler or exact domain workspace. Unknown and creative validation issues show read-only details; they cannot fall back to a synthetic approval.
- The synthetic review action verifies the current open intervention, exact synthetic workflow definition and matching run before resuming its hook.
- Timelines prefer recorded stage identities and attempts, including creative generation phases. A terminal run without a matching receipt displays missing/unrun evidence rather than future work or fabricated completion.
- Current worker presentation requires matching active task/stage/run records. Latest completed workers remain history.
- Working counts exclude queued, waiting and owner-review runs. Page-update connectivity is labelled separately from execution. Failed source reads remain visible instead of becoming authoritative zeroes.
- The control centre provides a direct next-action link. Shared controls and the creative workspace have readable graphite/cyan/amber surfaces, visible focus and reduced-motion support.

## Verification and rollout

Each phase requires lint, typecheck, the full test suite, production build, independent review and exact-commit release checks. Hosted Chromium uses deterministic, source-rendered owner fixtures with external network requests blocked. Captured desktop, 390px mobile and 320px reflow images are inspected before merge. Fixtures verify layout and contracts; they do not establish live provider qualification. Production acceptance is read-only.

The first phase leaves operational route structure unchanged. Reverting its source commit restores the earlier presentation and guards; it never replays an approval or reverses any external effect. Later shell changes retain existing deep links and a reversible presentation switch.

## Boundaries that remain open

- Geographic research and creative production retain their existing live-qualification status, exact consent, fresh quotes, allowance and receipt rules
- Technical image PASS is not product TEST, exact production approval, physical print validation or listing-image approval
- Printful product-write authority, authenticated file binding and physical placement evidence producers remain unavailable
- The native Manual/API product path does not implement an Etsy-linked product/variant bridge
- Supplier variant linkage and manual order-confirmation settings remain unverified
- Shop-specific all-in publication fee, currency and tax evidence remain unavailable
- Automatic order synchronization and paid fulfilment remain later Stage 22 work

No schema, credential, persistent permission, provider mutation or spending change is part of this UI phase.

## Phase 2: guided shell and bounded research

Five primary destinations are Control centre, Work, Library, Decisions and Connections. Activity is secondary; qualification tools and Packs remain in expandable Advanced. Existing URLs and owner authentication are preserved. Mobile uses five labelled bottom destinations and an in-flow More disclosure; connection updates mount once. `AGENTLABS_GUIDED_UI=legacy` restores the previous navigation shell and research form without modifying execution or replaying approvals.

The research kickoff is a three-step Goal → Scope → Review interface over the existing `startGeographicDiscovery` action. It preserves the exact six submitted fields, experimental status, bounded five/seven-call choice, fresh estimates, explicit owner allowance, scope consent and existing atomic semantic replay guard. No new planner or cross-stage executor exists. Drafts are versioned and owner-scoped in browser-tab session storage, never in a new database table; consent is never restored. Owner, input, quote or availability changes invalidate review consent.

A research detail gets its goal from the matching same-Business, same-run product experiment and persisted intent identity, or the equivalent saved intent artifact. Product, listing and publication stages show prerequisites, never inferred completion. Business-linked Research and Library routes validate the owner’s Business before filtering read sources and form choices. Unknown data remains visibly unavailable.

Route mapping preserves `/dashboard`, `/dashboard/workflows`, `/dashboard/products`, `/dashboard/artifacts`, `/dashboard/needs-you`, `/dashboard/accounts`, `/dashboard/history`, `/dashboard/packs`, `/dashboard/settings`, `/dashboard/worker-proof`, `/dashboard/model-router` and `/dashboard/worker-evaluations`. Printful and Etsy remain linked from Connections and contextual stage requirements. Provider and security settings are unchanged.

Phase 2 requires real client hydration tests for Back/reload, local draft ownership, quote/consent changes, duplicate submission, focus and responsive layouts. Their server action is a synthetic in-memory stub and all browser networking is blocked; no live paid research is part of UI release verification.
