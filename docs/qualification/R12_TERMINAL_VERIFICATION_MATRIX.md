# R12 terminal qualification: verification matrix

The useful outcome is a bounded, auditable research cycle. A genuine negative decision is valid evidence; it must not be converted into TEST to make a check green. The approved terminal attempt permits at most two research calls and USD 0.277907. Creative execution needs separate authority.

## Isolate before broad qualification

1. Reproduce the failing entry from its actual predecessor state and a clean parent-process environment. A prebuilt marked lineage is not coverage of its creation.
2. Exercise terminal-source creation, owner preparation and duplicate confirmation, activation, bounded progress, interrupted receipts/reload and Stop through shared real source with inert provider edges. Keep negative and concurrency evidence distinct from the happy path.
3. Run focused checks for the changed dependencies. A shared owner fixture affects both R12 SQL and Next qualification; its unit regression alone does not qualify those paths.
4. Run the final canonical aggregate once on the frozen candidate. Earlier green jobs are retained diagnostic evidence, not a current full pass. Any formal dependency-based reuse requires an explicit reviewed qualification rule.

The current defect is missing inert configuration in a test boundary process. Production rejects that condition correctly. Its fix must make the fixture representative; removing the rejection assertion would hide the defect.

The existing optional `--r12-only` runner still performs older base journeys in HTTP mode and all R12 journeys. It is not a terminal-only browser lane. A cheaper focused lane must select the same terminal journey and shared setup deliberately, without copying a reduced imitation or replacing the final aggregate.

## Focused diagnostics and final release

Draft PR updates and an explicit `focused` workflow dispatch select one focused job: the clean-environment regression, the exact terminal-entry native preflight, and `--r12-terminal-only` using the same actual Next journey assertions. The mode still builds the production application and captures the evidence snapshot needed by that journey; it omits unrelated journeys and unused capture sets.

Ready/non-draft PRs, main pushes and explicit `release` dispatches retain all twelve named checks. The release aggregate records the tested Git commit and tree and accepts only twelve successful required results. Focused, missing, skipped, failed or cancelled evidence cannot qualify a release. The aggregate intentionally remains red for a focused run, even if its diagnostic job passes; report those outcomes separately. No branch-protection setting changes are implied.

The runner's default remains full, and the workflow's explicit dispatch default is `release`. Main verification stays enabled. No caching, broad path filters or previous-run reuse are introduced in this change.
