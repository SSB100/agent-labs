# Reviewed fresh captures for the unused recovery

The guarded recovery release passed its complete qualification and reached Production. Its later live-authority question was unanswered, so the proposed full 30-minute execution plus 30-minute receipt window could no longer fit before the original source expiry. That packet expired unused: no recovery Goal, staging, verifier enrollment or paid call was created.

The existing recovery validator required the original observation array byte-identical, including retrieval dates and capture hashes. Honest new source reads therefore could not qualify. A generic new Goal or another pilot would violate the existing lineage/one-recovery boundary and is not used as a workaround.

## Changed invariant

Original observations and all historical scope, output, cost and closure records remain immutable. The same existing recovery authorization can optionally contain a versioned `evidenceRefresh` certificate. It binds the complete old/new addenda, observation arrays, learning references and every old/new observation pair to fresh owner and independent review evidence.

Each pair preserves exact source identity, URL, title, source kind, geographical role, countries, dimensions, and cited span positions. The cited factual substring must be byte-identical. Only retrieval/capture provenance, observation identity and explicitly reviewed surrounding context/limitations can change. Source access may stay the same or strengthen from a public search index to a public document read. Learning references map exactly to the corresponding new evidence/container/content hashes; candidate, question, success/failure measures, design constraints and budgets stay pinned.

The deterministic pair hash is an integrity binding, not evidence that a review or retrieval occurred. Before staging, the trusted operator must verify the actual captured-source records and an independent review artifact covering the exact complete old/new hashes, changed access/context/limitations, unchanged cited facts and experiment constraints. A factual-source review alone is not that independent bundle review. The new owner confirmation displays the fresh observations, access method, dates and limitations before approval.

Without a certificate, original exact-array/reference checks remain unchanged. The existing private validator still reconstructs the abandoned request and charged predecessor. The one-root/one-recovery slot, no further recovery, two calls, no paid retry, no search/image/store action, and all current-time funding/permission/source checks remain binding. The certificate is within the unchanged 16KiB authorization limit; profile and request bounds are unchanged.

## Authority and validation

The migration adds one private invoker helper and changes one existing private validator. It creates no table, public API, EXECUTE grant to API roles, credential, policy, activation, extra slot or provider call. Fresh enrollment still needs its own action-time approval; no old policy or time window is revived.

Qualification covers the unchanged old branch and a refreshed branch with genuinely changed capture method, contextual limitations and content hashes while preserving the cited facts. Negative cases must rebuild their hashes and still reject stale reads, reused reviews, missing or reordered pairs, source/fact/market substitution and changed learning references. The full native SQL, real HTTP dispatch/send/receipt/Stop sequence and actual Next preparation/confirmation/receipt-interruption journey remain required before release.

Local qualification passed twelve focused contract/routing tests and the four-test refreshed PostgREST gate in 94.7 seconds. Strategy/reviewer dispatch took 1629/1620ms; separate send took 885/932ms under its unchanged three-second bound. Twenty direct-SQL/operator-stage rejection cases, five final-send expiry faults, exact catalog/ACL preservation, later-than-original-expiry validation and actual Next fixture preparation/confirmation/activation/Stop passed. Two inert POSTs and receipts completed before authority closure.

The ordinary native run passed eleven tests, including all nine original/refreshed focused cases, then the local executor killed the pre-existing large-image legacy/creative replay. No assertion failed before termination, but no complete local aggregate pass is claimed. Final targeted lint, typecheck and diff checks passed. Independent source/security review approved the change. Canonical hosted legacy/creative and hydrated Next gates remain required on the final tree.
